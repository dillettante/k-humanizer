# 파일 형식별 서식 프로필 v0.1

## 공통 원칙

내용과 구조를 구분하라. 이모지·볼드·헤딩·불릿이 있다는 사실만으로 삭제하지 말고, 장르 기능과 파일 형식의 의미 정보를 확인하라.

## Markdown

- `#`·`##`·`###`, `**볼드**`, 목록 기호와 이모지를 기본 보존한다. Markdown 표지나 이모지를 AI 흔적으로 보고 삭제하지 않는다.
- 사용자가 산문화·서식 재설계를 명시했을 때만 구조를 바꾼다. 짧은 카드형 헤딩이 반복되어도 윤문본에서 임의 삭제하지 말고 대안으로만 제안한다.
- fenced code, HTML 주석, 인용 블록, 링크·각주 표지는 원문 구조다. 산문 윤문에서 건드리지 않는다.
- Markdown의 이모지는 장르와 무관하게 기본 보존한다. 단행본·법률·학술·보고서에 어울리지 않으면 삭제본을 만들지 말고 형식 대안을 `ask`로 제안한다.
- 윤문 후 `scripts/verify_markdown_structure.py`로 제목 순서·굵은 표지 수·이모지·코드 펜스를 exact 비교한다.

## DOCX

DOCX는 텍스트 표지가 아니라 OOXML의 문단 스타일·번호 매기기·run 속성을 읽어라. 먼저 `scripts/scan_docx_format.py`로 후보를 확인하라.

- `Heading 1~3`, `제목 1~3`, outline level이 있는 문단은 의미 있는 구조로 보고 기본 보존한다.
- Normal 본문에서 문장 대부분이 bold이거나 짧은 라벨형 굵은 문단이 연속될 때만 장식성 볼드 후보로 본다.
- Word의 실제 numbering/list 속성이 있는 문단은 불릿 문자만 보고 산문화하지 않는다. 절차·요건·체크리스트이면 보존한다.
- 단행본·에세이·법률·학술 프로필에서는 장식성 이모지를 삭제한다. 인용된 원문·제품명·표시 기호는 보존한다.
- 서식을 고칠 때에는 문서 XML을 풀어 해당 run·문단 속성만 국소 수정하고, 원본을 별도 파일로 보존한다. 내용 수정과 서식 수정을 같은 추적 변경에 섞지 않는다.

## HWP/HWPX

- 전용 HWP/HWPX 도구로 스타일·문단·글자 속성을 추출한 뒤 DOCX와 같은 의미/장식 구분을 적용한다.
- 변환 과정에서 제목·각주·표·책갈피가 평문으로 무너질 수 있으므로 단순 텍스트 변환본만으로 서식을 삭제하지 않는다.

## PDF

- PDF는 기본적으로 최종 출력물이다. 텍스트·서식 후보를 진단하되 직접 수정하지 않는다.
- 원본 DOCX·HWP·Markdown을 요청하고, 없으면 페이지·문단 위치와 권고만 보고한다.
- OCR 텍스트의 볼드·헤딩·불릿 추정은 불확실하다고 표시한다.

## 편집 가능 형식의 장르별 기본값

아래 표는 DOCX·HWP·HWPX처럼 서식 수정을 명시한 경우에 적용한다. Markdown은 위 보존 규칙이 우선한다.

| 장르 | 이모지 | 볼드 | 헤딩·목록 |
| --- | --- | --- | --- |
| 단행본·에세이 | 장식이면 제거 | 본문 장식은 해제 | 장·절 구조 보존, 카드형 분절은 검토 |
| 법률·학술 | 장식이면 제거 | 정의·결론·개정 표시 보존 | 요건·항목·논증 구조 보존 |
| 보고서 | 장식이면 제거 | 핵심 수치·표제 보존 | 실제 요약·절차 목록 보존 |
| 블로그·SNS·제품 안내 | 의도에 따라 보존 | 가독성 기능이면 보존 | 카드형 구조 허용 |

서식 자동 삭제는 사용자가 명시한 프로필과 명백한 장식 후보에만 적용하라. 판단이 갈리면 수정본에 반영하지 말고 `ask`로 제시하라.
