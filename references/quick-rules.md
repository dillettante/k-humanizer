# 빠른 위치 앵커 v0.6

`quick-rules.json`은 사람이 다시 읽을 위치를 찾는다. 횟수는 저자 판정·품질 점수·자동 수정 권한이 아니다. 한 표현의 분포와 문단 밀집을 함께 보고, 실제 기능이 있으면 보존하라.

## 결정적 앵커

| 층 | ID | 후보 |
| --- | --- | --- |
| 대구·결산·열거 | KH-S01~S03 | 부정 대구, 결산 라벨, 첫째·둘째 |
| 연결·번역·호흡 | KH-S04·S06~S09 | 문두 연결어, 원문 대조 피동, 연결어미 뒤 쉼표, 종결 연속, 완곡 |
| 번역투·형식명사 | KH-S11~S13·S15~S16 | `~에 대해`, `~을 통해`, `~라는 점/것`, 자동 피동, 영어 병기 |
| 과장·공식 | KH-S17~S21 | 의의 과장, `넘어 ~로`, `이는`, 목적절, 중복 수식 |
| 결말·안내 | KH-S26~S27 | `~다는 것이다/필요가 있다`, 글·장·절 안내문 |
| 중요성·성장 결산 | KH-S32 | 긴밀한 맞물림, 능동적 상호작용, 삶의 풍요, 핵심 습관 묶음 |
| 후편집 구조 | KH-S34~S37 | 장·절 선언, 장면 회귀 신호, 자명·열거 예고, 굵은 도입 라벨 연쇄 |
| 삼항 병렬 | KH-S40 | `-고/-며`로 이어진 세 항의 의미 기여도 검토 위치 |

KH-S05·S10·S14·S22~S25·S28~S31·S33은 문단·파일 형식·귀속·용어 이관 맥락을 읽어야 하므로 빠른 정규식만으로 확정하지 않는다. KH-S32도 단일 표현만으로 자동 수정하지 않고 문단 밀집과 기능을 읽는다. DOCX의 KH-S10·S28 후보는 `scripts/scan_docx_format.py`로 별도 진단하고, KH-S33 후보는 `scripts/audit_term_migration.py`로 모집한다.

KH-S34~S37은 `--provenance ai_edited`일 때만 스캔한다. 특히 KH-S35~S37은 장·파일 간 분포와 위치를 함께 읽는다. 한 작품 안의 액자 구성, 강조 목록, 의도한 논증 안내를 횟수만으로 고치지 않는다. KH-S40은 내력과 무관하게 삼항 병렬의 위치를 모집하지만, 의미 중복은 판정하지 않는다. 실제 절차·서로 다른 개념·법률 요건·의도한 점층은 보존한다.

직접 인용, Markdown 인용 블록, 명시 보호 블록, 수치·날짜·조문 표기를 포함하는 후보는 기본 스캔에서 제외한다. HTML 주석과 fenced code도 제외한다. KH-S08은 종결이 다른 문장과 보호 문장을 연속의 경계로 취급한다.

윤문 gate에 `--target-rule`을 지정했으면 해당 앵커가 실제로 줄어야 한다. 사람이 문맥을 읽고 의도한 용례로 판정한 항목만 `--preserve-rule`로 예외 처리한다.
