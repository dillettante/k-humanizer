# 반복 윤문·수렴 계약 v0.4

반복 윤문의 목표는 매번 다른 문장을 만드는 것이 아니라, 뜻과 형식을 지킨 채 지배 패턴을 해체한 한 버전에 수렴하는 것이다.

## 두 기준본

- `baseline`: K-humanizer를 처음 적용하기 전 원문. 주장·근거·조건·부정·양태·인과·귀속·격식의 최종 기준이다.
- `previous`: 직전 회차에서 채택한 본문. 새 결함과 불필요한 재수정을 찾는 기준이다.

2차 이후에는 두 파일을 모두 읽는다. `previous`만 읽고 다시 쓰면 앞 회차의 의미 손실을 정상 문장으로 오인할 수 있다.

## 회차별 작업

1. **1차—해체:** 지배 패턴 3~6개를 정하고 표준 인간화를 수행한다.
2. **2차—교정:** baseline과 1차를 문장별로 대조한다. 의미·강도·격식 손실, 새 공식 표현, 불분명한 주체, 형식 훼손만 고친다. 새 문체 실험은 하지 않는다.
3. **3차 이후—정지 시험:** 전문을 다시 읽되 기본 출력은 무수정이다. 새로 확인된 결정적 결함만 국소 수정한다.

사용자가 다섯 번 검수를 요청해도 다섯 개의 서로 다른 윤문본을 만들 필요는 없다. 검수 회차와 수정 회차를 구분한다.

## 회차 대장

| 위치 | baseline 의미 | 1차 판정 | 현재 상태 | 다시 여는 조건 |
| --- | --- | --- | --- | --- |
| 문단·문장 | 원자 명제·양태 | `edit·preserve·ask·false_positive` | `해결·보존·미해결·신규·되살아남` | 새 의미 손실·새 결정적 표지·사용자 지시 |

`해결`과 `보존` 위치는 잠근다. 단순히 다른 표현이 떠올랐다는 이유로 다시 열지 않는다.

## 정지와 롤백

다음을 **모두** 사람이 확인했을 때에만 직전 채택본을 그대로 반환하고 `수렴`으로 기록한다.

- 새 `edit` 항목이 없다.
- 남은 앵커가 문맥상 필요한 열거·대조·양태여서 `preserve` 또는 `false_positive`다.
- `ask·미해결·신규·되살아남` 항목이 없다.
- baseline의 주체·부정·정도·시제·가능성·의무·미래 양태가 그대로다.
- 제안된 수정이 뜻·격식·호흡 중 어느 것도 분명히 개선하지 않는다.

다음이면 최근 수정을 취소하고 앞 회차를 다시 채택한다.

- `중요하다→도움이 된다→중요하다`처럼 판단 강도나 표현이 왕복한다.
- 1차에서 없앤 결산어·추상 포장이 유사어로 되살아난다.
- 더 자연스럽게 만들려다 구어적 부사, 새 비유, 새 인과가 생긴다.
- 앵커 총계는 줄었지만 의미·형식 gate가 실패한다.

앵커 수는 품질 점수가 아니다. 자연스러운 열거를 복구하면 KH-S07 수가 늘 수 있고, 필요한 대조를 복구하면 KH-S01이 다시 잡힐 수 있다. 총계보다 위치별 판정을 우선한다.

## 기계 확인

```bash
python3 scripts/audit_iterations.py \
  --baseline original.md \
  --version pass-1.md \
  --version pass-2.md \
  --version pass-3.md
```

도구는 baseline 식별자·해시, 최초본·직전본 대비 변경량, 무수정 회차, 무수정 뒤 재수정, 문서 전체가 이전 회차와 같아지는 exact 왕복, Markdown 구조 변화를 보고한다. 10만 자를 넘는 비교는 문자 단위 `SequenceMatcher`를 실행하지 않고 행 단위 대체 지표를 낸다. 이때 `changed_character_ratio`는 `null`이며 `changed_line_ratio`는 변경 문자 비율이 아니다. 같은 파일쌍은 한 번만 측정해 무수정 회차의 중복 비용을 피한다. 문장 일부의 왕복은 회차 대장에서 사람이 확인한다. 도구의 `기계 확인 완료`는 수렴 판정이 아니다. 의미 보존과 자연스러움은 사람이 baseline과 회차 대장을 대조해 판정한다.
