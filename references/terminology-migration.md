# 용어 이관·후유증 검토 계약 v0.2

용어를 잘 고르는 일과 확정한 용어를 원고에 안전하게 이관하는 일은 다르다. 전역 치환은 끝이 아니라 새로운 문장 검토의 시작이다. 하나의 기존어가 맥락별로 다른 의미라면 전면 치환하지 말고 [selective-terminology.md](selective-terminology.md)의 용례 결정 대장을 쓴다.

## 1. 용어 결정을 잠가라

책·보고서·번역문에서 용어를 바꾸기 전에 다음 term map을 만든다.

```json
{
  "schema_version": "0.1",
  "terms": [
    {
      "id": "review-order",
      "source": "review hierarchy",
      "old": ["검토 위계"],
      "new": "검토 순서",
      "scope": ["body"],
      "exceptions": [
        {
          "text": "과거에는 검토 위계라 불렀다",
          "reason": "역사적 명칭",
          "document_id": "chapter-1",
          "scope": "body",
          "line": 42,
          "occurrence": 1
        }
      ],
      "rationale": "서열보다 적용 차례를 뜻함",
      "do_not_use": ["검토 등급"],
      "components": ["검토", "순서"]
    }
  ]
}
```

- `source`: 번역 원어 또는 개념 출처. 원문이 없으면 비워 두고 충실성을 단정하지 않는다.
- `old`: 기존 번역어·표기. 여러 개면 모두 적는다.
- `new`: 사용자가 확정한 정식 용어. 공개 스킬의 보편 번역표가 아니라 해당 원고의 결정이다.
- `scope`: 본문·용어집·표·제목·각주·색인 가운데 실제 적용 범위다.
- `exceptions`: 인용·고유명·과거 용례 설명처럼 바꾸지 않을 **정확한 한 위치**를 `document_id`·`scope`·`line`·`occurrence`로 찍고 이유를 남긴다. 같은 문자열의 다른 출현까지 예외로 얼리지 않는다. 두 파일 중 하나에서라도 지정 위치를 찾지 못하면 보류한다. 따옴표·Markdown 인용·명시 보호 블록의 기존어는 자동으로 잔존 실패에서 제외하되 결과에 따로 센다.
- `rationale`와 `do_not_use`: 선택 이유와 버린 대안의 충돌을 짧게 남긴다.
- `components`: 띄어쓰기가 없는 복합어의 되풀이까지 찾으려면 구성어를 명시한다. 생략하면 공백으로 나뉜 두 글자 이상의 구성어만 자동 추출한다.

확정어 자체는 보호한다. 문장을 자연스럽게 만들겠다고 동의어로 다시 흩뜨리지 않는다.

## 2. 이관 범위를 고정하라

1. manifest에서 포함 문서와 용어집·표·제목·각주·색인의 포함 여부를 기록한다. 문서별 `scopes`는 `body·glossary·table·heading·footnote·index` 가운데 실제 포함 영역을 적는다.
2. 기계 치환 전후 파일을 모두 보존한다.
3. 기존어 잔존과 확정어 출현 수를 파일별·scope별로 센다. 본문에서 지운 용례를 제목에 추가한 용례로 상쇄하지 않는다.
4. 예외는 위치와 이유를 기록한다. 잔존 0건을 만들려고 인용이나 역사적 명칭을 고치지 않는다.
5. `전수 이관`은 scope의 모든 파일을 검사했을 때만, `전수 문맥 검토`는 확정어의 모든 용례를 사람이 읽었을 때만 말한다.

```json
{
  "schema_version": "0.1",
  "documents": [
    {"id": "chapter-1", "before": "before/chapter-1.md", "after": "after/chapter-1.md", "scopes": ["body", "heading"]},
    {"id": "glossary", "before": "before/glossary.md", "after": "after/glossary.md", "scopes": ["glossary"]}
  ]
}
```

## 3. 확정어 주변을 다시 읽어라

각 확정어가 들어간 문장과 앞뒤 한 문장을 읽고 다음을 확인한다.

| 층 | 확인 질문 | 처리 원칙 |
| --- | --- | --- |
| 동어반복 | 확정어의 구성어가 정의나 가까운 문장에 되풀이되는가? | 확정어는 두고 서술어·정의 방식을 바꿈 |
| 조사·호응 | 옛 용어에 맞춘 조사·수식·종결이 새 용어와도 맞는가? | 가장 작은 주변 구문만 수정 |
| 연어 | 주어와 서술어, 단위와 측정 동사가 한국어에서 자연스럽게 결합하는가? | 원문 기능과 원고 내부의 강한 용례를 함께 확인 |
| 개념 범위 | 더 쉬운 말로 바꾸면서 범위·정도·전문적 구별이 좁아지거나 넓어졌는가? | 원어·용어집·정의와 대조하고 불확실하면 `ask` |
| 제목·표 | 제목의 압축이나 표의 열 이름이 본문과 같은 기능을 하는가? | 본문 문장을 기계적으로 복사하지 않음 |
| 인접 용어 | 비슷한 지표어·회계어·법률어와 혼동되는가? | 원고 내부 용어집을 우선하고 충돌 이유를 기록 |

전역 치환으로 `X 순서는 … 순서다` 같은 문장이 생기면 `X 순서`를 다시 변주하지 말고 정의부를 고친다. 자동으로 검출할 수 없는 연어와 개념 범위는 사람 판정이다.

## 4. 직역 은유와 제목을 분리해 보라

은유라는 이유만으로 고치지 않는다. 다음 세 조건을 함께 본다.

1. 주변 문단이 같은 뜻을 더 직접적이고 정확하게 이미 말하는가.
2. 은유가 논지를 밝히는가, 원문의 공간·신체 이미지만 옮겨 관계를 흐리는가.
3. 같은 원고의 지표어·전문용어와 충돌하는가.

제목이 `A는 B다`, `A가 아니라 B다` 같은 은유 등식·부정 대구라면 절의 첫 문단과 대조한다. 절이 실제로 답하는 질문을 가리거나 첫 문장을 반복하면 질문형·행위형 제목을 후보로 제시할 수 있다. 그러나 제목의 수사 기능이 살아 있으면 보존한다.

형식명사와 부정 대구는 KH-S13·S01, 추상 주어의 직역 은유는 KH-S14, 영어 병기 자체는 KH-S16, 전역 이관 후유증은 KH-S33으로 분리한다.

## 5. 기계 감사와 사람 판정

```bash
python3 scripts/audit_term_migration.py \
  --manifest migration-manifest.json \
  --term-map term-map.json
```

한 파일만 다루면 `--before`, `--after`, 반복 가능한 `--scope`를 쓴다. 도구는 manifest scope 누락, 기존어 잔존, 확정어 전후 계수 차이, 확정어가 든 문장, 명시 구성어 되풀이 후보를 보고한다. Markdown scope 분리는 제목·표·각주 시작 행을 구분하는 보수적 행 기반 휴리스틱이다. 구조가 겹치면 `각주·제목 → 표 → 본문`의 우선순위로 한 번만 센다. 복잡한 다중 행 표·각주는 전용 문서로 나누거나 사람이 범위를 확인한다. 기존어가 사라졌는데 새 확정어 수가 그만큼 늘지 않으면 문장 삭제·병합 가능성을 `보류`한다. 정당한 병합은 사람이 근거를 기록한다.

`기계 확인 완료`는 의미 보존, 연어·개념 적합성이나 전수 문맥 검토의 통과가 아니다. 각 후보를 `edit·preserve·ask·false_positive`로 판정하고, 확정어의 모든 용례를 읽지 않았다면 그 범위를 그대로 밝힌다.
